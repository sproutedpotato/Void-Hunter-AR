## 📌 프로젝트 개요
* **개발 기간:** 2025.01 ~ 2025.11 (11개월, 졸업 작품)
* **팀 구성:** 3인 개발 (기획 1, 개발 2)
* **장르:** 3D AR 모바일 FPS
* **핵심 역할:** 플레이어 및 몬스터 전투 로직, 피격 시스템 구현

## 🚀 기술적 도전 및 해결 과정 (Key Challenge)

### 1. 인터페이스를 활용한 몬스터 관리 체계 구축
다양한 종류의 몬스터가 등장하는 게임 특성상, 각 몬스터의 세부 로직을 알 필요 없이 공통된 동작을 수행할 수 있는 구조가 필요했습니다.
* **해결 방법:** `IDamageable`과 같은 **인터페이스를 정의**하여 모든 몬스터가 이를 상속받도록 설계했습니다.
* **성과:** 무기 시스템(총알, 수류탄 등)에서 특정 몬스터 클래스에 의존하지 않고 인터페이스 하나로 데미지 전달 및 상태 제어가 가능해졌으며, 새로운 몬스터 추가 시에도 기존 시스템의 수정 없이 유연하게 대응할 수 있는 확장성을 확보했습니다.

### 2. 정밀한 피격 판정: 부위별 차등 데미지 시스템
FPS 게임의 전략성을 높이기 위해 단순 충돌을 넘어선 정밀한 피격 시스템을 구현했습니다.
* **해결 방법:** 몬스터 모델의 각 부위(Head, Arm, Leg 등)에 별도의 콜라이더를 배치하고, 각 콜라이더마다 **데미지 배율(Multiplier) 스크립트**를 할당했습니다.
* **성과:** 헤드샷(200%), 팔/다리(50%) 등 부위별로 차등화된 데미지 로직을 완성하여 게임의 긴장감과 완성도를 높였습니다.

### 3. 코드 아키텍처에 대한 반성: 상속과 추상화의 조화
인터페이스 사용으로 확장성은 챙겼으나, 공통 기능의 중복 작성이 발생하는 아쉬움이 있었습니다.
* **반성 및 개선:** 인터페이스는 '행위'를 정의하고, **추상 부모 클래스(Abstract Base Class)**는 '공통 기능(예: 이동, 사망 로직)'을 구현하는 구조로 설계했어야 함을 깨달았습니다. 
* **학습 성과:** 이 경험을 통해 객체 지향 프로그래밍(OOP)에서 **인터페이스와 상속의 적절한 조화**가 코드 재사용성에 얼마나 큰 영향을 미치는지 깊이 이해하게 되었습니다.

## 🛠 Tech Stack
* **Engine:** Unity 6 (6000.0.33f1) / AR Foundation
* **Language:** C#
* **Tools:** Git, Visual Studio
* **Key Skills:** 3D Vector Math, Raycasting, Interface-based Design
